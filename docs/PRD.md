# ZonePick 产品需求文档

状态为初稿，待项目负责人评审。项目定位和长期范围沿用[项目章程](PROJECT_CHARTER.md)。模块分工与运行环境详见[技术架构](ARCHITECTURE.md)和[开发环境](ENVIRONMENT.md)。

## 1. 项目目标与使用场景

ZonePick 是一套可配置的多麦克风目标区域语音增强与可视化仿真平台。用户以空间区域为拾音条件，从多说话人混合观测中提取区内语音，并在同一声学条件下比较不同算法。

| 用户 | 使用场景 |
| --- | --- |
| 算法开发者 | 配置阵列和声学场景，验证区域拾音、算法接口和基线实现。 |
| 科研人员 | 固定数据划分与指标口径，复现实验并进行对照和消融分析。 |
| 项目展示及实习面试体验者 | 观察声源、阵列和区域的位置关系，试听处理前后的语音，查看对比结果。 |

## 2. 用户核心流程

1. 配置声源、麦克风阵列和房间，选择目标区域。
2. 生成多通道混合音频，并按评估协议另存目标与干扰参考。
3. 选择处理算法及其参数。学习型算法按需指定已有模型。
4. 执行离线增强，试听参考通道的未增强音频和增强语音，比较可用指标与图形。
5. 保存运行记录，用同一输入重跑或切换算法进行对照。

| 阶段 | 输入与产出 |
| --- | --- |
| 仿真数据生成 | 根据几何、语料、RIR 和随机种子生成多通道观测及独立参考。 |
| 模型训练 | 使用指定训练与验证集、区域条件和监督目标更新参数，产出带版本的检查点。 |
| 模型推理 | 根据混合观测、可获得的空间条件和已有检查点生成增强结果。传统算法可直接处理。 |
| 实验评价 | 读取增强音频、未增强基线与可用参考，按固定协议计算指标并记录结果。 |

## 3. 声学场景

长期支持可配置的多说话人数和多麦克风阵列。第一版候选场景为两个静止说话人、五通道阵列、一个区内说话人与一个区外干扰者，具体配置待评审。

| 配置项 | 要求 |
| --- | --- |
| 声源 | 提供每个声源的坐标、语音文件标识、起始时间与增益，记录语料来源和使用许可。 |
| 麦克风阵列 | 使用与声源一致的坐标系和单位，定义各麦克风坐标、通道顺序和参考麦克风。 |
| 房间与 RIR | 记录房间尺寸、可用的混响或吸声参数、RIR 来源及生成或选择方式。 |
| 音频与随机性 | 指定采样率、片段时长和随机种子，记录重采样、裁剪及随机采样规则。 |

几何仿真根据配置的房间、声源和麦克风位置生成模拟 RIR，结果须标为仿真。测量 RIR 应关联实际房间、测量时的源和麦克风位置及通道映射，只能作为对应测量配置的记录。若后续使用插值或近似，应标注其方法和适用范围。MVP 的 RIR 来源及仿真工具待评审。

## 4. 目标区域

目标区域用场景坐标中的空间几何描述。说话人编号用于关联音频和元数据，区域归属由声源位置与几何边界决定。长期支持预设与自定义区域。第一版候选为二维圆形区域，由圆心和半径定义，声源按同一平面的投影判定。坐标投影、区域形式及以下行为均待评审。

| 情况 | 候选行为 | 状态 |
| --- | --- | --- |
| 一个区内说话人 | 输出该声源的单通道增强语音。 | 待评审 |
| 多个区内说话人 | 长期比较合并为单通道与逐人输出。MVP 候选是提示当前场景超出支持范围。 | 待评审 |
| 无区内说话人 | MVP 候选是返回可读的无目标提示，并标记参考型指标不可用。静音输出策略后续讨论。 | 待评审 |
| 声源在边界 | 候选为圆周计入区域，数值容差与测试样例一并确认。 | 待评审 |
| 区域与真实声源位置 | 仿真真值用于生成监督和评价参考。常规推理接收用户选择的区域，基线可由区域圆心确定指向。需要定位结果的算法应声明其可获得的来源。 | 待评审 |

## 5. 算法与统一接口

长期保留传统阵列信号处理（如 DAS、MVDR）、神经网络与传统算法结合（如 NN Mask + MVDR）、纯神经网络目标区域语音提取三条路线。MVP 先验证一个传统算法基线，DAS 为待评审的首选。其余两条路线进入后续阶段。

统一推理接口接收多通道波形、采样率、阵列坐标、通道顺序、参考通道、区域几何和算法参数。模型版本由学习型算法按需传入。第一版候选输出为单通道增强波形、采样率、时间对齐信息和运行标识。三条路线最终使用相同测试场景、混合观测和指标口径进行比较。

常规推理仅使用运行时可获得的输入。使用理想掩码、仿真真实位置、真实方向或独立干净源音轨的实验应标记为 Oracle，并记录所用额外信息、结果和适用条件。验收时检查常规推理在评价参考缺席的情况下仍可运行。MVP 可以只运行常规基线。若开展 Oracle 对照，评价记录须显式标明实验类型和额外输入。

## 6. 网页可视化

长期支持场景配置与位置显示、目标区域选择、算法切换与模型加载、未增强及增强音频试听、波形与频谱展示、评价指标对比，以及训练和实验结果管理。

v0.1-B 优先用预设场景展示声源、阵列和区域，使用应用层运行 v0.1-A 的基线，显示结果并提供试听。完整场景编辑器、模型管理和训练管理放在后续版本。所有算法调用复用统一应用层，网页负责交互、任务状态和展示。首版区域交互和图形范围待评审。

## 7. 实验与评价

每次运行记录配置快照、随机种子、代码提交、环境版本、数据来源与划分、模型或检查点版本、输入及输出产物和评价协议。训练、验证、测试使用可追踪的数据划分，规定说话人或语音片段是否需要跨划分隔离。三条路线在同一测试集比较，报告参考通道未增强基线、增强结果及各自的运行条件。

仿真需要保存参考信号的定义、采样率、通道、对齐和混响口径。第一版候选用参考麦克风处的独立目标分量作为参考，计算至少一项定义明确的指标，例如 SI-SDR。SIR 的干扰分量来源、计算条件、空目标与静音的处理均待评审。没有干净参考的真实录音只能提供试听、图形或适用的非参考指标，参考型指标应显示为不可用并记录原因。

## 8. 非功能性需求

- **可复现性**要求保存并重跑固定小样例，在约定容差内核对输出。记录设备、依赖和数值差异，容差待评审。
- **可测试性**要求对音频维度、采样率、区域判定、参考缺席和指标口径编写可独立运行的检查，并提供离线端到端样例。
- **可维护性**要求 CLI 与网页复用应用层。算法与界面各自演进，共享配置和结果结构。
- **运行兼容性**要求首版命令行闭环在本地 WSL2 的 CPU 上可运行。需要加速的学习型方法应声明 CPU 与 GPU 支持范围及设备依赖。学校 GPU 服务器用于后续较大规模训练。
- **资源限制**要求记录测试音频时长、运行时间、峰值内存及适用的峰值显存。首版面向短片段离线任务，明确支持范围并对超出范围的输入给出可读错误。具体上限与性能预算待评审。
- **许可与公开仓库安全**要求记录语料、RIR、模型和第三方代码的来源及许可，确认再分发权限。提交前检查凭据、本机敏感配置、私有语料和大型生成产物，公开样例使用获准发布的内容。

## 9. MVP 阶段与验收

两阶段均为待评审方案。验收关注闭环、可复现性和结果可读性，算法提升目标在取得实验数据后评审。

| 项目 | v0.1-A 命令行算法闭环 | v0.1-B 最小网页可视化 |
| --- | --- | --- |
| 范围 | 用一个预设仿真场景完成配置、混合、传统基线、评价与保存。 | 复用 A 的任务流程，在浏览器运行预设并展示场景、试听和指标。 |
| 输入 | 场景配置、获准使用的短音频、区域、算法参数和随机种子。 | 预设场景、目标区域和可用基线。 |
| 输出 | 五通道混合、参考通道未增强音频、单通道增强结果、配置快照与评价记录。 | 声源、阵列与区域视图，未增强和增强试听，指标及运行状态。 |
| 测试 | 检查通道顺序、采样率、区域内外与边界、重复运行、缺参考推理和无效配置。 | 检查网页可提交同一应用任务，且同一运行的两段音频、指标和场景正确关联。覆盖任务失败时的可读提示。 |
| 验收 | 在本地 WSL2 CPU 从已保存配置重跑样例。产物可读取，指标对应所选参考协议，复跑差异符合评审后的容差。 | 打开本地网页并运行预设，核对位置关系，试听两种音频，查看至少一项可解释指标。用与 CLI 相同的配置比较结果，差异符合约定容差。 |

优先评审以下决策。

- **声学样例（FR-001）**，双说话人、五通道阵列的几何布局、采样率、房间参数、语料、RIR 来源和仿真工具。
- **区域语义（FR-002）**，二维投影与圆形参数，区内一个或多个声源、无声源及边界的行为，区域描述和定位信息的来源。
- **基线与评价（FR-003 至 FR-005）**，DAS 是否作为首个基线，指向与参考通道定义，干声或含混响的参考口径，指标、对齐和数据划分。
- **网页与运行预算（FR-006、NFR-001、NFR-002）**，首版区域交互与图形、网页框架、可接受误差、音频时长、内存和运行时间预算。
- **后续模型与存储（FR-007、FR-008）**，模型条件编码、训练和 GPU 环境、实验与检查点存储方案。
